The fast path

Three skills. Two files. Ship anyway.

Describe what you want, get an architecture doc and a flat task list, then build tasks one at a time — each with a failing test first, an isolated QA pass, and your own hands-on sign-off before it counts as done. Speed comes from deleting ceremony, not from deleting checks.

Three skills

start → build → ship

A strict linear order with nothing to route between. Works on Node, Rust, Python, Go, Ruby, PHP and C/C++ — the stack is resolved from your manifest and lockfile, then written down once so it is never guessed again.

start// when: a project needs its plan

Writes docs/ARCHITECTURE.md (stack, folder structure, decisions with reasons, and the project's real test/build/lint commands) and tasks/PLAN.md (a flat list of small tasks with acceptance criteria). Works on a new idea, an existing codebase, or an existing plan you want to extend — re-runs append tasks and never clobber your edits.

$ /ck-code-lite:start "a habit tracker with a weekly streak view"
build// when: implementing one task end to end

Picks the next ready task, asks its one round of questions, then runs the loop: a failing test per acceptance criterion, the minimum code to pass, a bounded cleanup, an isolated QA pass, and a manual-test gate. No implementation file is created until a test run has been observed failing.

$ /ck-code-lite:build T-02
ship// when: committing finished work

Conventional commit with a body a non-engineer can read, then opens a pull request — or appends to the one already open rather than overwriting it. Resolves the base branch from the remote default instead of asking. Works standalone on any git repo, with or without a plan behind it.

$ /ck-code-lite:ship
What lite does not cut

Four gates that still hold

Every one is written as an absolute rule, not a suggestion. These are the reason lite is fast rather than merely sloppy.

A failing test before the code

No implementation file is created or edited until a test run has been observed failing. No test runner in the project? build stops and asks — it never proceeds pretending the step happened.

QA against every criterion

Delegated to an isolated subagent that runs your project's own commands and returns a verdict with file:line citations — so unbounded suite output never floods the session.

Manual sign-off

You get concrete steps to try and are asked for the result. Answering ISSUES writes a regression test and loops back through QA — it does not ship.

Clarify before building

One batched question round on genuine ambiguity, before anything is written. Nothing ambiguous means no questions at all — a ceremonial round is treated as a defect.

Never a guessed command

Commands come from your manifest, lockfile and declared scripts. (none) is a valid answer; an invented npm script is not.

No AI references

Nothing this plugin writes to git mentions Claude, AI, or "generated by". Commits and PRs read as if a person wrote them. Absolute and non-overridable.

The whole state model

One table, one section per task

There is no generator, no index and nothing to regenerate. Every task ID appears on exactly three lines — the table row, the header, the meta line — so grep -n "T-02" tasks/PLAN.md is the entire consistency check. Break it with an editor and you can fix it with an editor.

IDTitleStatusSizeNeeds
T-01User can sign in with emaildoneM—
T-02Session survives a page reloaddoingST-01
T-03Signing out clears the sessiontodoST-02

Statuses are todo, doing, done, blocked — nothing else parses. Tasks are S or M only; anything larger gets split before it is written. A task is ready when it is todo and everything in Needs is done.

Choosing

ck-code-lite or ck-code?

They are alternatives, not companions — enable one per project. Both expose build and ship, and running a project through both layouts will not end well.

Slash commands

Quick reference

CommandWhat it does
/ck-code-lite:startCreate or extend docs/ARCHITECTURE.md and tasks/PLAN.md. Accepts a feature description or a spec-file path; empty re-runs append to the existing plan.
/ck-code-lite:buildImplement one task end to end. Optional task ID such as T-03; with no argument it picks the next ready task interactively.
/ck-code-lite:shipCommit and open or update a PR. Optional task ID; runs standalone on any git repo when there is no plan.
Install

Same marketplace as ck-code

Add the marketplace once, then install whichever plugin fits the project.

$ /plugin marketplace add ckandrinirina/ck-code
$ /plugin install ck-code-lite@ck-marketplace

ck-code-lite stays dormant until a project enables it. Add "enabledPlugins": { "ck-code-lite@ck-marketplace": true } to that project's .claude/settings.json — and don't enable ck-code alongside it in the same project.
