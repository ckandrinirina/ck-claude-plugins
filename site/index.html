Why use it

The AI works at file level. You plan at architecture level. They drift.

If you've used Claude Code on a real project, you've felt the gap. Specs go stale, stories get re-implemented, tests get skipped under deadline pressure, and PRs end up loosely related to the original requirements. CK plugins close that gap.

Without a workflow

  • Architecture lives in your head, not in the repo
  • Tests skipped when the deadline gets close
  • The same story implemented twice, differently
  • PRs that don't trace back to a requirement

With CK plugins

  • One source of truth from spec to merged PR
  • No production code without a failing test first
  • Experts auto-generated from your architecture
  • Branches, commits, PRs and Issues stay linked

What you get

Discipline, built into the loop

Architecture docs, automatically

Your spec becomes self-contained per-feature design docs — folder structure, components, APIs, data flow, database schema — in docs/architecture/.

TDD enforced, SOLID checked

Red → green → refactor. No production code ships without a failing test first, and every implementation is reviewed against SOLID principles.

Experts tailored to your stack

ck-code reads your architecture and generates only the expert roles and language guides the project needs — refreshed with up-to-date best practices via context7.

Parallel builds in worktrees

Fan unblocked stories out across isolated git worktrees, build them at once, and get a conflict report before anything merges.

GitHub-native, end to end

Push epics and stories to labelled GitHub Issues, then keep branches, commits, PRs and Issues linked automatically through to merge.

A board that tells the truth

Story cards move themselves: Ready to Ship when the work is finished, In Review once a PR is open, Done only when it reaches the trunk branch. Merge in the browser and the next sync catches it, board or no board.

Token-lean by default

Per-skill effort tuning, read-only tool hardening and dynamic context injection cut tokens and round-trips — pair with /fast for small stories.

Get started

From spec to shipped in a handful of commands

Install once, enable per project, then walk the workflow. Here's a first run in a new project with ck-code.

$ /plugin marketplace add ckandrinirina/ck-code
1
/ck-code:design

Generate per-feature architecture documents from your spec (it finds the spec for you).

2
/ck-code:team

Create the expert & language-guide skills your stack needs.

3
/ck-code:plan

Break the architecture into epics and sized stories, and pick once whether PRs go per story, per epic or per plan.

4
/ck-code:build

Implement the next story with TDD and the built-in QA loop.

5
/ck-code:verify

Hand-test the assembled feature from a checklist; issues go straight to fix.

6
/ck-code:ship

Commit with conventional commits, open a PR, update the Issue and move the card.

7
/ck-code:track

See what is ready, what is in review, and what actually reached the trunk.

Per-project opt-in. Installing doesn't activate the plugin everywhere. Add "enabledPlugins": { "ck-code@ck-marketplace": true } to a project's .claude/settings.json to switch it on — unrelated repos stay clean.

FAQ

Questions people ask first

What is ck-code?

ck-code is a free, open-source plugin for Claude Code that brings spec-driven development to AI coding. It turns a project spec into architecture docs, epics and sized stories, builds each story with test-driven development and an isolated QA pass, walks you through a manual test checklist, and ships commits, pull requests and GitHub Issues.

How do I install a CK plugin in Claude Code?

Run /plugin marketplace add ckandrinirina/ck-code, then /plugin install ck-code@ck-marketplace (or ck-code-lite or ck-tools), and restart Claude Code. Enable it per project by adding "enabledPlugins": { "ck-code@ck-marketplace": true } to the project's .claude/settings.json.

Should I use ck-code, ck-code-lite or ck-tools?

Use ck-code for features and products that deserve architecture docs, epics, parallel builds and GitHub tracking. Use ck-code-lite to ship a small app or prototype fast with four skills and two files. Use ck-tools alongside either one, or on any repository, for commits, pull requests, dependency upgrades, issues and releases.

Are the plugins free?

Yes. All three plugins are open source under the MIT License. You only need Claude Code; the gh CLI is needed for GitHub Issue features.

Does ck-code work on an existing codebase?

Yes. /ck-code:init sets ck-code up on an existing codebase without a spec: it checks the tools ck-code needs, then reads your docs and code and writes the architecture as built. After that, ck-code scopes each new feature against that architecture and generates only the new epics and stories. A ck-code-lite project upgrades to ck-code with /ck-code:migrate.

How does ck-code keep AI-written code correct?

Every story is built test-first: a failing test, then the minimum code, then a refactor, with SOLID checks and an isolated QA pass. Before a feature is promoted, /ck-code:verify walks a person through a manual test checklist that resumes where they stopped, and hands any issue to /ck-code:fix.
