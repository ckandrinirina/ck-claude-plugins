ck/plugins / ck-tools
Utility toolkit plugin

The work around the feature, handled.

ck-code delivers features. ck-tools does the surrounding work — implementing quick tasks, filing issues, upgrading dependencies, preparing releases and committing changes. Each skill is independent, re-callable and project-agnostic.

Install ck-tools Browse the skills
Five skills

Composable, audit-trail-first utilities

Works with Go, Node, Python, Rust, Java and more. Skills detect your package manager, framework and conventions before acting, and ask before touching anything remote.

deliver// when: you want to commit & maybe open a PR

Commit staged or unstaged changes with a conventional-commit message and optionally open a pull request. Project-agnostic — no story or epic format required.

$ /ck-tools:deliver "fix: handle empty upload"
implement// when: a quick feature, fix or refactor on any stack

On-the-go story implementation. Writes a dated STORY.md, asks for approval, optionally links a GitHub Issue, applies SOLID design and review (skipped only for trivial changes), implements, runs tests and lint, then asks for final sign-off before marking done.

$ /ck-tools:implement "add pagination to the users endpoint"
dependency-upgrade// when: a quarterly / yearly dependency sweep

Phased, snapshot-tracked dependency upgrade. Each cycle is a self-contained dated folder, so the same repo can upgrade every quarter with a permanent audit trail. Re-callable to resume an in-progress cycle.

$ /ck-tools:dependency-upgrade --new
gh-issue// when: file one issue from intent or a story file

Create a single GitHub Issue from free-text intent or a story file, with optional assignment to a GitHub Project. Mirrors gh issue create flag style.

$ /ck-tools:gh-issue "flaky test in auth suite" --label bug
release-prep// when: cutting a production release

Diff source vs. target branch, summarize PRs in plain language for non-developers, update CHANGELOG.md with PR links, bump the version file (package.json / pyproject.toml / Cargo.toml / VERSION), and print an annotated git tag command. Multi-language output. Never auto-commits, pushes or tags.

$ /ck-tools:release-prep dev main --lang=en
Design principles

Why it's safe to keep around

Independent skills

Each skill is self-contained and re-callable. No cross-skill state to manage.

Audit-trail first

Every version-changing action writes a snapshot before and after. The diff is the receipt.

Date-scoped cycles

Recurring work lives in dated folders so multiple cycles coexist without overwriting history.

Explicit confirmation

Anything that writes to a remote — commits, PRs, Issues — asks first. No silent side-effects.

Repo-aware

Detects the package manager, framework and project conventions (via CLAUDE.md) before acting.

Zero-token formatting

A PostToolUse hook auto-formats edits (prettier / rustfmt / ruff / black / gofmt) at no model-token cost.

Slash commands

Quick reference

CommandWhat it does
/ck-tools:deliverCommit with a conventional-commit message and optionally open a PR. Accepts an optional change description.
/ck-tools:implementImplement a feature, fix or refactor. Free-text task + optional --story <path> to resume.
/ck-tools:dependency-upgradeStart or resume a dependency-upgrade cycle in the current repo. --new forces a fresh cycle.
/ck-tools:gh-issueCreate a GitHub Issue from a description or --story. Flags: --project, --label, --assignee.
/ck-tools:release-prepPrepare a release from source → target branch. Flags: --lang, --bump, --prerelease, --dry-run.
/ck-tools:bmad-guideOrient yourself in a BMAD Method project. Detects the installed BMAD version, explains the flow, says where you are and which workflow to run next. Optional task or question, e.g. add payments to my app.
Install

Same marketplace as ck-code

Add the marketplace once and install whichever plugins you need — they're built to coexist.

$ /plugin marketplace add ckandrinirina/ck-code
$ /plugin install ck-tools@ck-marketplace

Like ck-code, ck-tools stays dormant until a project enables it. Add "enabledPlugins": { "ck-tools@ck-marketplace": true } to that project's .claude/settings.json.

Two plugins, one workflow

Use ck-tools on its own, or pair it with ck-code for the full design-to-ship loop.
