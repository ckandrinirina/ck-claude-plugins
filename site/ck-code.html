ck/plugins / ck-code
Spec-driven workflow plugin

Keep architecture, plan and code in lock-step.

Feed ck-code a project specification and it produces architecture docs, an epic/story plan, a per-project expert team, and a TDD build-and-ship loop — all from inside Claude Code. AI-generated code stays grounded in your real design.

Install ck-code See all commands
The workflow

Five stages, one source of truth

Each stage hands a concrete artifact to the next. Nothing is reconstructed from memory — the spec, the docs, the plan and the code all trace back to the same place.

1

Design

Spec → per-feature architecture docs.

2

Plan

Architecture → epics & sized stories.

3

Team

Generate experts & guides for your stack.

4

Build

Implement each story with TDD + QA.

5

Ship

Commit, PR, update GitHub Issues.

Highlights

What's in the box

Automatic architecture docs

Split markdown in docs/architecture/ — overview, folder structure, tech stack, components, data flow, API contracts, database schema, dev guide.

Epic & story planning

Stories sized S/M so one agent finishes each in a pass, with explicit dependency graphs in tasks/.

TDD enforcement

Red/green/refactor cycle. No production code without a failing test first.

SOLID checks

Every implementation is reviewed against single-responsibility, open/closed, Liskov, interface-segregation and dependency-inversion.

Project-tailored experts

Auto-generated per-project expert and language-guide skills, refreshed via context7 for current best practices.

Parallel multi-story builds

Implement unblocked stories at once in isolated git worktrees, with conflict analysis before merge.

GitHub Issues integration

Push epics and stories to Issues with size labels and parent/child links; PRs and Issues stay connected.

Capability-tier model selection

Agents pick the right Claude tier (fast / balanced / advanced) per story size — no hardcoded model IDs.

Token-lean by default

Per-skill effort tuning, read-only tool hardening and dynamic context injection cut tokens and round-trips.

Example of use

A greenfield project, start to finish

Say you have a one-page spec for a task-tracking API in docs/specifications.md. Here's the whole loop.

first run — new project
›# 1 · architecture docs from the spec
›/ck-code:design docs/specifications.md
›# 2 · experts + language guides for your stack
›/ck-code:team --standard
›# 3 · epics and sized stories
›/ck-code:plan docs/specifications.md
›# 4 · (optional) push the plan to GitHub Issues
›/ck-code:ship --to-issues --mode stories
›# 5 · find the first story, then build & ship it
›/ck-code:track next
›/ck-code:build
›/ck-code:ship

After /ck-code:team, your .claude/skills/ holds experts/{frontend,backend,qa,…} (invoked as /expert-frontend, etc.) and guides/{rust,axum,react-native,…} auto-loaded when relevant files are touched — all tailored to the architecture you fed in.

Command reference

Every ck-code skill

CommandPurposeOutput
/ck-code:specGenerate a stakeholder-ready feature spec for review (no code/jargon); revises an existing slug or Issue URL.feature spec & optional Issue
/ck-code:designRefine a spec into feature-scoped architecture docs; optimize token-diets them, sync scaffolds missing ones.docs/architecture/
/ck-code:teamDerive per-project expert + guide skills (depth --basic/--standard/--max); offers house-rules capture inline at the plan prompt (--conventions re-runs it alone); --workflow runs the big fan-outs as resumable scripted workflows..claude/skills/expert-* & guide-*
/ck-code:planCreate epics, sized stories and a roadmap; --quick adds one small story to an existing epic.tasks/ + FEATURE_INDEX
/ck-code:trackProgress dashboard — status, next story, progress.status report
/ck-code:buildImplement stories with TDD + QA — one inline, many at once in parallel worktrees (story IDs), or a whole epic in waves (--epic NN); implements a triaged bug story in Bug-Fix Mode.source code + tests; conflict report in parallel mode
/ck-code:fixDiagnose & triage a bug — records a failing repro test + Fix Plan, then routes to build.diagnosis + regression test
/ck-code:shipCommit (conventional), open a PR, update GitHub Issues; --to-issues publishes a plan to Issues.commit + PR + issue updates
/ck-code:explainExplain what was just implemented, with verification steps.walkthrough
/ck-code:guideRouter — recommends the next step, routes a task to the right skill, looks up command syntax.recommendation
/ck-code:migrateOne-shot upgrade of a pre-v5 project — or a ck-code-lite project — to the v5 layout (frontmatter, generated indexes, flat team-skill folders); stamps tasks/VERSION.md.v5 layout + VERSION.md
When to use it

Where ck-code shines

Greenfield projects

Go from a one-page spec to a full tasks/ plan, architecture docs and a per-project expert team in a single session.

Feature additions

ck-code reads your current architecture, scopes the feature, and generates only the new epics and stories.

Disciplined AI coding

Enforce TDD and SOLID even in long autonomous sessions — the build loop won't ship untested code.

Parallel team builds

Fan unblocked stories across worktrees and let agents build in parallel, with conflict analysis before merge.

GitHub-integrated planning

Turn a story plan into a labelled, linked Issue tree with a single command.

Up-to-date practices

Expert skills are refreshed via context7 so guidance reflects current framework docs.

Install

Add the marketplace, install, restart

$ /plugin marketplace add ckandrinirina/ck-code
$ /plugin install ck-code@ck-marketplace

Then enable it per project. Add this to the project's .claude/settings.json — without it the plugin stays dormant, keeping unrelated repos free of the workflow:

{ "enabledPlugins": { "ck-code@ck-marketplace": true } }

Requirements: Claude Code (required), gh CLI for Issue features, git for parallel builds, and context7 (recommended) for up-to-date framework docs. See the full README on GitHub for compatibility and v3 migration notes.
